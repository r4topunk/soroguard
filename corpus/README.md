# corpus/

This directory contains a snapshot of **deployed mainnet Soroban WASM bytecode**,
one file per contract, fetched on **2026-09-17 (UTC)** from the public Stellar
mainnet RPC (`https://mainnet.sorobanrpc.com`) via `getLedgerEntries`
(through `@stellar/stellar-sdk`'s `getContractInstance` /
`getContractWasmByContractId` helpers). It is the evidence base every number in
the top-level `README.md` and `docs/` is computed from — it is committed
bytecode, not a build artefact, and must not be deleted or regenerated
casually.

## Files

- `<CONTRACT_ID>.wasm` — the raw WASM module deployed at that contract id, 71
  files, ~2.4 MB total.
- `index.json` — the manifest, keyed by contract id:

  ```json
  {
    "<contractId>": {
      "wasmHash": "<sha256 hex of the .wasm file>",
      "bytes": <file size in bytes>,
      "at": "<ISO-8601 UTC timestamp of when it was fetched>"
    }
  }
  ```

  Entries that were discovered but not kept as `.wasm` files carry `skip`
  (`"SAC or no wasm"`, `"duplicate wasm"`) or `error` instead of `wasmHash`/`bytes`.

- `calibration.json` — the aggregated detector-triage output for this corpus
  (contract/entrypoint counts, findings per class, suppression reasons),
  generated by `node scripts/calibrate.mjs`.

## Verifying the bytes are genuine

`wasmHash` in `index.json` is the sha256 of the corresponding `.wasm` file.
Anyone can confirm the committed bytes are exactly what's deployed on-chain:

```sh
shasum -a 256 corpus/<contractId>.wasm
# compare against index.json[<contractId>].wasmHash
```

This was spot-checked on 3 files during the initial commit and all matched.

## Regenerating

```sh
node scripts/fetch-corpus.mjs [targetCount]
```

- `targetCount` (optional, positional, default `300`) — how many distinct
  contracts (by unique wasm hash) to collect before stopping.
- The script is resumable: it re-reads `corpus/index.json` on start and only
  retries contracts that are still missing or previously failed with a 429.
- It discovers candidate contract ids from recent contract events, then
  fetches each candidate's contract instance and wasm with low concurrency,
  inter-call pauses, and exponential backoff to stay under the public RPC's
  rate limits.
- Contracts with no wasm executable (e.g. Stellar Asset Contracts) or with a
  wasm hash already seen (duplicate bytecode) are recorded in `index.json`
  with a `skip` reason and are not written as `.wasm` files.

Regenerating `calibration.json` after any corpus or detector change:

```sh
node scripts/calibrate.mjs
```

This runs the full detector taxonomy over every `.wasm` file in this
directory and writes the aggregated triage (contracts, entrypoints, findings
by class/STRIDE category, suppression reasons) to `corpus/calibration.json`,
also printing a summary to stdout.


## Contracts withheld

Four contracts that were part of the original 75-contract corpus are not in this directory: they carry findings that are under private disclosure to their maintainers (see `SECURITY.md`). They will be restored once disclosure completes. Every number in the repository is computed over the 71 files present.
